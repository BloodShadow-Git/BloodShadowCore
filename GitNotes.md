# 🚀 Шпаргалка по Git: Чистая история в один коммит (VS Code)

## 🏷️ Стандарты именования веток (Интенты)

Название ветки должно отражать ваше намерение. Пишите префиксы через слэш / — VS Code сгруппирует их в удобные папки.

* feat/имя-фичи — Создание новой логики, фичи, кнопки (например: feat/dark-mode).
* fix/что-сломалось — Исправление багов и ошибок (fix/login-error).
* chore/что-делаем — Рутина: плановые обновления либ, изменение конфигов (chore/scheduled-update, chore/deps-upgrade).
* refactor/что-меняем — Переписывание кода под новое API или улучшение читаемости без изменения логики (refactor/api-v2-migration).
* docs - Работа с документаций, также допускается вариант с docs/`имя_файла` для конкретизации файла
* update/имя-фичи - Изменение логики конкретной фичи

## 🔄 Полный цикл работы: От создания до слияния в ОДИН коммит

### Этап 1: Создание ветки и работа

Перед стартом всегда обновляем dev, чтобы писать код на базе самого свежего проекта.

#### 1. Переходим на dev и скачиваем обновления с сервера

```bash
git checkout dev
git pull origin dev
```

#### 2. Создаем новую ветку и сразу переходим на неё

```bash
git checkout -b feat/my-new-feature
# *(Пишем код, делаем сколько угодно промежуточных коммитов в процессе работы)*
git add .
git commit -m "feat: набросал интерфейс"
git add .
git commit -m "feat: исправил мелкую опечатку"
```

### Этап 2: Проверка «на берегу» (Перед слиянием)

Если за время вашей работы dev ушел вперед, решаем конфликты в своей безопасной ветке, а не в общем dev.

#### 1. Уходим на dev и обновляем его

```bash
git checkout dev
git pull origin dev
```

#### 2. Возвращаемся в свою фичу и вливаем в неё обновленный dev

```bash
git checkout feat/my-new-feature
git merge dev
```

*💡 Если VS Code подсветил конфликты: выберите нужные строки кнопками Accept..., сохраните файлы и завершите мерж: git add . && git commit -m "fix: разрешил конфликты".*

### Этап 3: Слияние через Squash (Все коммиты схлопываются в ОДИН)

Теперь переносим изменения в dev так, чтобы история осталась идеально чистой.

#### 1. Переключаемся на главную рабочую ветку dev

```bash
git checkout dev
```

#### 2. Сплющиваем все коммиты вашей фичи в один большой комок изменений

```bash
git merge --squash feat/my-new-feature
```

#### 3. Создаем тот самый ОДИН финальный коммит для истории dev

```bash
git commit -m "feat: полностью готовая и протестированная фича"
```

#### 4. Отправляем чистый dev на GitHub/GitLab

```bash
git push origin dev
```

### Этап 4: Уборка

Код уже на сервере в dev, локальная фича-ветка больше не нужна.

```bash
git branch -d feat/my-new-feature
```

## 🛠️ Скорая помощь: Если накосячил

### «Я случайно написал коммит прямо в ветку dev (локально)»

Откатить dev назад, сохранив коммит в новой ветке (пока не сделан git push):

```bash
git branch feat/saved-feature     # Создает ветку поверх вашего коммита
git reset --hard HEAD~1           # Стирает коммит из истории dev
git checkout feat/saved-feature    # Переходит в спасенную ветку
```

### «Я уже отправил (push) ошибочный коммит из dev на GitHub»

*Внимание: безопасно, только если репозиторием пользуетесь только вы!*

```bash
git branch feat/saved-feature     # Спасаем коммит в ветку
git checkout dev
git reset --hard HEAD~1           # Чистим dev локально
git push origin dev --force       # Силой перезаписываем чистый dev на сервере
```

## ⚡ Быстрые клавиши и лайфхаки для VS Code

* git checkout - — Вернуться на предыдущую ветку, в которой вы были шаг назад.
* git branch -a — Посмотреть список всех веток (и локальных, и на сервере).
* git push <remote_name> :<branch_name> - для удаления удалённой (на сервере) ветки
* git fetch <remote_name> <branch_name> - насильно вытянуть ветку с репозитория
* git reset --hard <remote_name>/<branch_name> - принудительно сбросить локальные изменения
